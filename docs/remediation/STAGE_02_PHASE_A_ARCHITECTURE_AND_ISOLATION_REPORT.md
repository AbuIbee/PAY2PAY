## A6. Concurrency and duplicate-submission scenarios

The existing suite already covers extensive real-PG concurrency for the broader webhook/retry system: `B06` (concurrent duplicate webhook delivery), `B07`/`B08` (processing-lease expiration/contention), `B18`/`B18b` (stale-worker fencing), `B25`/`B25b` (concurrent lifecycle decisions), `B31`/`B32` (failed-payment retry races against a genuinely-held installment lock, both orderings), `R-B40-STRICT-A/B/C` (success-wins / retry-wins / ambiguous-response races, using `createIsolatedDb`'s genuinely separate real connections — not the same shared, `max: 1` connection — per `test/postgres/testDb.ts`'s own stated purpose), and `R-B57`/`R-B58` (bounded-batch starvation avoidance for many permanently-ambiguous claims). **This order's own §A6 asks specifically about "two competing recovery workers or repeated same-key dispatch."** `R-B40-STRICT-B` ("the installment lock is genuinely held through the real provider call; a concurrent coordinateSuccess is proven blocked") is exactly this shape for the coordinator's OWN retry-dispatch path — it is the closest existing analogue to "two competing recovery workers," though it pairs a retry dispatch against a competing SUCCESS (not against a second competing retry-dispatch attempt on the SAME retry row). A literal "two workers race to claim and dispatch the SAME `payment_retry` row" scenario specific to 008-C/F/I's own dispatch path was not found as a named existing test; the schema's own `executionToken` column (minted only at claim time, re-confirmed immediately before the real provider call, per its own doc comment) is the mechanism that would need to be exercised. **This report does not propose adding this as a NEW Stage 2 requirement** (it is not named in this order's own five-item acceptance target) but flags it as an adjacent, currently-unproven scenario worth the owner's awareness — Phase C should not manufacture a new acceptance criterion here without separate authorization, per this order's own scope-discipline instruction ("Avoid broad unrelated redesign"). Same-batch supersession is not included in Phase C's proposed scope on this same basis — no source analysis performed this phase established it as already on a tested recovery path for 008-C/F/G/H/I specifically, and manufacturing that analysis without a clearer mandate would risk exactly the "broad unrelated redesign" this order prohibits.
