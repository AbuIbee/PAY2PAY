# PAY2PAY PRSPRINT CONTROL

**Repository destination:** `docs/prsprints/PRSPRINT_CONTROL.md`

## Purpose

This file is the authoritative execution tracker and approval gate for the Production Ready Sprint program.

## Control Rules

1. Execute one PRSprint at a time.
2. Do not begin the next PRSprint until the current PRSprint has completed implementation, verification, CI, deployment checks where applicable, Supabase verification where applicable, Product Owner review, and merge where required.
3. Any `FAIL`, `PARTIAL`, `CRITICAL`, or unresolved `HIGH` finding blocks progression unless explicitly accepted by the Product Owner.
4. External provider dependencies must be recorded as `EXTERNAL BLOCKER`. Sandbox functionality must never be recorded as production-ready.
5. Product Sprint 19 is separate from PRSprint 19 and remains frozen until explicitly released by the Product Owner.
6. Claude must never mark its own Product Owner review as approved.
7. Every PRSprint must stop after its completion report.
8. Protected baselines (see below) must be checked before any PRSprint touches a protected file; violating a protected baseline blocks merge regardless of CI status.

## Protected Baselines

A protected baseline is a previously Product-Owner-approved behavior that must not be modified,
refactored, renamed, replaced, or altered by a later PRSprint unless the active PRSprint has an
unavoidable direct dependency on it and the change is explicitly required — never as an opportunistic
refactor.

### PRSprint 11A: authentication/session baseline

Approved by the Product Owner. Full analysis, root cause, and fix: see
`docs/prsprints/PRSPRINT_11A_LOGIN_AUTHENTICATION_REGRESSION_REMEDIATION.md`. Permanent regression
suite: `src/app/api/auth/login-logout-cycle.test.ts` (plus `src/lib/rate-limit.test.ts` for the
fail-open behavior specifically).

**Protected behavior:**
- account creation
- valid login
- session creation
- session cookie handling
- session persistence after refresh
- current-session logout
- visible Sign Out UI
- mobile authenticated topbar/navigation
- business-context cleanup on logout
- protected-route denial after logout
- browser Back protection after logout
- direct protected-URL denial after logout
- login again after logout
- repeated login/logout cycles
- individual account authentication
- business account authentication
- Platform Admin authentication
- Platform Owner authentication
- the PRSprint 11A fail-open behavior around rate-limit storage failures (`checkRateLimit` in
  `src/lib/rate-limit.ts`), unless a later dedicated remediation explicitly replaces it with a proven
  production-safe alternative

**Before merging any future PRSprint that touches authentication/session-related files:**
1. Identify the exact PRSprint 11A-protected files affected.
2. Explain why the change is unavoidable.
3. Run the PRSprint 11A authentication regression suite (`src/app/api/auth/login-logout-cycle.test.ts`,
   `src/lib/rate-limit.test.ts`, `src/app/api/auth/login/route.test.ts`,
   `src/app/api/auth/logout/route.test.ts`).
4. Prove: signup PASS, login PASS, session persistence PASS, logout PASS, login-after-logout PASS,
   protected-route denial after logout PASS.
5. If any of those fail, do not merge.
